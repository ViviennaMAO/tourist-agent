# 第七轮：车辆和窗洞细节

## 本轮结果
- 迪拜的 18 辆环境车辆替换为程序化轿车：真实轮拱缺口、四个轮胎、五辐轮毂、倾斜前后风挡、分片侧窗、后视镜、门把手、细门缝、格栅、保险杠压线及前后灯组。
- 六种低饱和车漆。全车队共八个材质实例批次，每车含四轮约 8,024 三角面。车轮按行驶距离转动，同一环境时间可复现。轮胎底部对应原路面 Y=1.38；含后视镜半宽 0.76，保留在 1.65 宽车道内。
- 原随机路线与不同车速会让车辆互相重叠，换成长车身后尤其明显。迪拜车流改为沿现有主岛矩形环路双向、每向九辆等距巡游，共用较低速度。其他城市车流不变。这是景观车流，不是具备停车、避人或红绿灯的交通模拟；拐角仍沿原线段切换方向。新增车距逻辑在 A/B 模式下也生效，A/B 只恢复车辆几何与材质。
- 传统建筑侧窗补齐石质窗框侧壁、窗台阴影缝、分层压线，局部加入褶帘与百叶，避免所有窗口完全重复。调整玻璃色调/反射强度，略减石材贴图压暗和凹凸强度。
- 建筑水平包围范围与拱廊纵深不变；不新增行走障碍。Eva 图片角色和植物资源沿用上一轮。
- 审查页增加“车辆细节”，在真实车流位置将环境定格到 180 秒并设置相机。正常游戏无该面板。

## 验证
- `npm run check`、`npm test`（18/18）、`npm run build`、`git diff --check` 通过。构建保留 Three vendor chunk 大于 500 kB 的已有提示；游戏业务包约 251 kB（gzip 93 kB）。
- 新测试涵盖双向车距、路由原数据保护、轮拱射线空洞、轮胎落地、几何有限值与预算、实例变换/轮毂旋转、定格、原模型恢复和独占资源释放。
- 建筑碰撞边界测试曾发现新增窗台压线外伸 0.02，已将其内收，并重新通过所有测试。
- 浏览器检查桌面 1440×900、窄屏 390×844，游戏启动、车辆近景、街区动画、门窗近景及精修开关恢复正常；54/54 地标加载，运行错误 0。此台桌面浏览器稳定观测约 116–120 FPS，载入/切换场景时约 94–102；窄屏是尺寸模拟，不代表手机真机性能。
- `validation/round-7/street-before.png`、`facade-before.png` 来自 f00d15a；对应 after 保持相机和环境时间 180 秒。车流分布发生改变，不能逐车对应前后位置。
- `vehicle-original-toggle.png` 为本轮关闭街区精修时的旧车辆，不是上一提交的整体场景。`vehicle-after.png` 为同相机同车位的新车。截图均为游戏实时渲染，未使用生成图片替代。

## 范围与限制
本轮没有新增外部模型、纹理或生成式素材。玻璃仍为不透明环境反射近似，没有完整室内、真实折射或逐帧局部反射探针；车辆是微缩游戏尺度下的程序化近似。摄影级参考图仍是后续目标。
