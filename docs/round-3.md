# 第三轮：迪拜滨海街区

2026-11-02。以用户提供的迪拜滨海参考图为方向，继续独立 tourist-agent 的 Explore 改造。

## 本轮结果

- 覆盖主岛23栋建筑。近处改成至少两层的石灰岩建筑；后排高层压低为不超过12–17.2单位的背景。水平占地不变，高度不再强求与原楼一致。真实凹窗、入口拱券、暖色店窗、金属栏杆、木格栅、壁灯和阳台花箱；部分屋顶有廊架和风塔。
- 24棵棕榈使用上一轮的细叶片结构。新增32处街景碰撞占地，包括花池、小乔木、座椅、灯具、咖啡桌伞和滨海小喷泉。新增物品先检查原道路、建筑与地标的保留区域，再检查本轮其他物品；开关恢复时只移除自身碰撞体。
- 滨海铺地、两层不规则岸石；隐藏原沙滩伞及卡通海岸线，关闭本轮可恢复。
- 海洋改用五层解析波法线、Fresnel混合和太阳高光；迪拜湖面、喷泉共用时间与着色。没有SSR、场景倒影、流体模拟或几何波浪。天空增加蓝色大气梯度及程序化薄云。
- 哈利法塔改为三翼逐级收分的银灰色程序模型，保留原地标holder以继承位置、导航和拾取；相框和博物馆保留原网格，改用更中性的金属表面。不是精确的建筑测绘模型。
- 普通玩家默认启用本轮，评审页保留第三轮/第二轮/第一轮/原始外观对照。Eva界面形象沿用上一轮，玩家和NPC仍为原Q版模型。

## 验证

- 6项Node测试通过：两轮建筑几何边界、有限顶点、演员矩阵恢复、碰撞体反复开关/销毁、海水源shader恢复、异步到达的地标素材及材料恢复。
- 语法检查、生产构建通过。无新增npm依赖；Three.js分包仍有大于500kB的构建提示。
- 浏览器54/54地标成功加载；评审页运行错误0、控制台error记录0。
- 固定1440×900、DPR1、阴影2048²、环境180秒。街区镜头 camera=(-353,12,-230), target=(-368,3,-255)：第二轮320,035 triangles /129 calls；第三轮527,576 /139 calls。本次记录约120 FPS，是桌面短时快照，不代表手机或持续性能。
- 新滨海镜头 camera=(-367,40,-152), target=(-354,18,-258)：660,698 triangles /524 calls，可见5/11城市；该镜头覆盖范围大，不与街区数字直接比较。
- 390×844正常玩家页面：按住上方向键1秒后出现哈利法塔介绍，东京快捷按钮成功传送，城市导览及世界地图可用。真实手机GPU尚未验证。
- 实际截图位于 `docs/validation/round-3/`：`street-round2.png` 与 `street-after.png` 同机位同环境；另有滨海全景、手机行走和地图。截图未作图像增强。

## 与参考图仍存在的差距

本轮是可玩的实时程序化场景，尚未达到参考图的离线效果。参考图里丰富的建筑体块、细密铁艺、扫描级石材、自然植被的透光和软接触阴影仍需专门资产及渲染迭代。当前背景楼群、车辆、部分地标和Q版角色仍有简化感。下一阶段宜聚焦一个临街建筑组，制作更准确的体块、材质和植被资产，先在近景达到目标后再扩展。
