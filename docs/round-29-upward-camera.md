# 第二十九轮：塔底仰视与相机控制

范围：tourist-agent / Explore，未修改原始项目。基线 6b50c87。

## 原因与改动

探索模式的 OrbitControls.maxPolarAngle 原来是 1.38 弧度（小于水平视线的 π/2），鼠标和单指都不能拖到仰视。视线自动回到人物身边，以及飞行完成后将最大距离恢复到 90，也限制了高楼构图。

- 探索模式开放约 82° 仰角，保留地图俯视约束，不允许翻转到极点。
- 镜头到达地面上方 1 个场景单位后，镜头和观察目标一起抬升以保留仰角；继续仰视时保持当前水平位置，避免绕目标运动将镜头拉进塔身。此保护针对地形、路面与桥面，不是完整的建筑相机碰撞系统。
- 用户拖动后进入自由观察，走动时保持观察方向；R 或“重置视角”按钮清除惯性并回到 Eva 身后。鼠标滚轮和双指缩放保留。输入框内的 R 不触发重置。
- 常规观察最大距离扩大到 240；飞行完成时保留当前构图所需距离，避免突然拉近。
- 验收界面增加“塔底仰视”机位；正常游戏也支持仰视，不依赖验收模式。

## 验证

69 项测试、语法检查及生产构建通过。新增 6 项回归测试直接使用项目安装的 Three.js OrbitControls，通过鼠标和单指 pointer 事件驱动，验证：

- 横屏 16:9、竖屏 9:16 从塔底向上拖动后，哈利法塔顶部参考点 (0,47.34,-33) 的投影进入视窗。
- 镜头保持地面净空，不被拉入塔底，松手后视角稳定。
- 重置排除剩余拖动惯性，恢复人物朝向后方的位置。
- 地图保留俯视限制，返回探索后恢复仰视能力；高处地面保护不改变观察方向。

这是控制器事件与投影的自动验证，不是浏览器截图验收。当前会话缺少可用的浏览器技能文件，未声称完成最新 WebGL 画面的人工复核；塔身近景材质、建筑遮挡和完整移动设备性能仍待实景检查。
