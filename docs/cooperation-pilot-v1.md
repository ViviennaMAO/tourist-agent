# 城市旅行护照 · 合作演示版 v0.1

## 当前交付

- 独立 tourist-agent 项目；默认运行迪拜、阿布扎比，14 个地标、10 个室内。拉斯维加斯保留在 `CITY_LIBRARY`、`INTERIOR_LIBRARY` 中，运行配置不加载它。
- 模拟购票、订单生成、余额和赠券已从运行代码移除；历史 localStorage 数据不被读取、迁移或删除。
- 旅行面板包含灵感、地点、行程和护照。17 张地点卡覆盖 14 个场景地标与 3 个滨水行程地点。
- 两城 10 个室内各有 3 段 Eva 文本讲解，与细节镜头同步，支持跳过、收藏和打开现实地点卡。不是语音导览或已接入的 AI 助手。
- Marina Mall → 商场前滨水步道 → Pier 7 半日草案可以一键保存；收藏支持按城市排序、移除和下载文本。
- 官方链接与真实地图是外部服务入口，不会生成本地“预约成功”或支付成功。
- 护照仅记录云游与收藏；真实到访和消费成长显示尚未接入，不能自报生成。
- `/?view=trip` 不加载游戏、Three.js 或远程地标模型，可独立使用地点与行程；用户选择进入室内时才加载 3D。
- `/partner-brief.html` 是面向合作会谈的英文单页提案，未发送给任何机构。

## 模块边界

`edition.js` 控制可见城市；`travel-catalog.js` 管理现实地点、来源、行程和室内讲解；`travel-state.js` 处理本机记录及事件白名单；`travel-experience.js` 提供原生 dialog 与轻量界面；`travel-shell.js` 连接场景；`entry.js` 支持轻量模式与 3D 加载失败兜底。

场景位置只用于云游。真实地图按独立地点名称查询，不使用场景坐标。海港模型明确为主题创作，Dubai Harbour、Dubai Marina 和 Bluewaters 分开说明。

## 信息核验

2026-11-05 检查官方来源；地点卡保留来源链接与日期，不缓存票价或营业时间。

- [Marina Mall 官方常见问题](https://www.dubaimarinamall.com/faqs/)：滨水层等到访信息。
- [Visit Dubai：Marina Walk](https://www.visitdubai.com/en/places-to-visit/marina-walk)：滨水步道目的地资料。
- [Emaar 社区：Pier 7](https://www.ecm.ae/en/communities/dubai-marina/discover/whats-around/pier-7-dubai-marina/)：与 Marina Mall 的步行联系及餐饮目的地。
- [未来博物馆](https://museumofthefuture.ae/en/)：核验时官网提示展览暂时关闭，卡片保留日期与提醒。
- [Jumeirah Burj Al Arab](https://www.jumeirah.com/en/stay/dubai/jumeirah-burj-al-arab-a-jumeirah-icon)：官网修缮信息，不承诺当前可进入。
- 其他来源链接维护于地点数据；所有外链仅打开信息，不表示合作关系或预订确认。

## 本机事件与数据限制

新键：`ta_travel_passport_v1`、`ta_travel_events_v1`。事件最多保留最近 200 条，仅在当前浏览器，不上传。保存城市、地点与动作等有限字段，不记录外链查询串、个人姓名、邮件或付款信息。

`/?view=pilot-review` 可查看并下载本机事件，不需要加载 3D。历史记录读取时也执行字段白名单与时间戳检查。

记录入口、兴趣、地点、室内、细节镜头、导览完成、收藏／移除、路线保存、行程／护照打开、地图／官网跳转、回到场景。“导览完成”只表示三处细节均已呈现，不证明用户阅读理解。

没有 booking-confirmed、arrival-verified、payment-confirmed 或积分事件。当前不能计算总体漏斗、真实转化、D7 或商家收入。入口可用 `?entry=itinerary` 做人工任务测试；并未开启随机 A/B 实验。

| 时间 | 操作 | 说明 |
| --- | --- | --- |
| 0:00–0:25 | 欢迎页，指出两种入口 | 游客可短时云游，也能直接看行程；不需要充值 |

## 人工用户测试（待安排真实参与者）

10 名目标游客，覆盖行前和在途；其中 5–8 人完成两条路径。另访谈 3 家商家。当前没有真实受试者结果。

1. 从欢迎页发现海滨体验，保存一条行程。记录用时、第一动作、卡住位置和是否需要提示。
2. 不进入游戏，找到一个指定地点的地图与官方信息。记录点击步数与误解。
3. 调整行程、下载、刷新后找到收藏。询问是否以为已经预约或付款。
4. 查看护照，解释云游和真实到访的区别。若认为游玩可赚 PWC，即判定表述需修正。
5. 商家访谈：可提供的服务、资料更新责任、可核验回执、接入意愿及现有结算方式；不承诺尚未确认的费用和结算时效。

## 验证命令

`npm run check`、`npm test`、`npm run build`。

浏览器验收脚本：`scripts/verify-travel.mjs`，使用 Playwright Core。可通过 `PLAYWRIGHT_MODULE` 指定模块、`CHROMIUM_PATH` 指定本机浏览器、`PLAYWRIGHT_BROWSERS_PATH` 指定含 FFmpeg 的运行目录、`TOURIST_TEST_URL` 指定本地或部署 URL。输出目录由 `QA_OUTPUT` 指定。脚本检查十个室内、手机布局、保存与重载、下载、排序、移除、旧数据隔离及无 3D 的行程入口，并单独保存地标加载状态。设置 `REQUIRE_ALL_ASSETS=1` 才要求远程资源全部达到 14/14。


## 2026-11-05 验收记录与限制

- 152 项单元测试通过；语法检查、Vite 生产构建与 diff 空白检查通过。
- 已复核桌面与 390×844 手机布局，十个室内导览、现实地点卡、行程保存／重载／排序／移除／下载，以及旧模拟资产隔离。
- 英文合作单页、轻量入口与本机事件导出在浏览器通过检查。不存在服务端事件统计。
- 原有资源站存在明显下载波动：一次严格资源验收等待 300 秒仍未完成 14/14，因此不宣称全部远程地标已通过本轮冷启动验收。功能验收记录资源状态，不能替代资产完整性验收。
- 为避免外部地标拖住旅行入口，场景初始化后最多等待 4 秒即可开始旅行；室内主题场景不依赖这些远程地标。户外地标仍在后台加载，慢网下会暂时显示占位。轻量行程不请求远程资源站。
- 原有 Three.js 与场景 bundle 超过 Vite 500 kB 提醒阈值；轻量入口已拆分，两者不会在该入口加载。正式合作展示前仍应做远程地标资源交付与实际移动设备性能优化。
