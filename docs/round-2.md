# 第二轮：迪拜西侧街区精修

2026-11-02。独立 tourist-agent 仓库和现有 Vercel 项目，只改 Explore。

## 范围与实现

- 西侧广场附近两栋 shops：真实墙带/窗间柱和约 0.235 单位深凹窗、细金属窗框、入口檐口、二层栏杆、女儿墙。按原坐标、旋转、占地和高度构建，保留现有碰撞体。
- 第一版近景检查发现单层窗上盲墙过高；调整为 h>=4.6 时两层，窗顶跟随层高。同时降低立面石材纹理对比和凹凸强度。
- 9 棵棕榈：13 枝羽状叶冠、细叶片、渐细环纹树干。使用3个 InstancedMesh，沿用现有 actor 的摆动矩阵。只替换 x∈[-34,5]、z∈(-50,-10) 的已生成棕榈。
- 通过 `Ctx.buildings/palms` 保存实例元数据；精修模块在每帧原 actor 更新后隐藏对应基础实例。关闭或销毁模块时恢复最新矩阵，其他实例和共享材料不被覆盖。
- 新增评审街区镜头：局部 camera=(-8,12,0)，target=(-23,3,-25)。原三组镜头不变。
- `reviewDetail` 独立开关可比较第一轮和第二轮；`look=original` 仍可关闭整个写实层，`detail=off` 仅关闭本轮几何。普通游戏不显示开发评审控件。

## 验证

- `npm run check`、`npm test`、`npm run build` 通过。构建保留 Three.js >500kB 的提示，未新增运行时外部依赖。
- 几何测试覆盖单/双层阈值、旋转 footprint/高度边界、所有属性有限值、最新 actor 矩阵恢复、未选棕榈不变、重复 dispose；建筑模块另有48组开发 fixture 检查。
- 1440×900，DPR1，2048²阴影，环境固定180秒，街区第一轮基线 298,937 triangles / 171 calls；第二轮 332,927 triangles / 181 calls。净增33,990三角面和10 calls；本机快照约118–120 FPS，非持续压力测试或手机性能承诺。
- 同参数广场第二轮 360,663 triangles / 305 calls；第一轮记录为326,673 / 295。
- 浏览器54/54地标加载成功，评审计数0运行错误，控制台未记录错误。
- 390×844普通玩家界面：按住上方向键1秒，角色前进并弹出哈利法塔卡；世界地图11城入画、Esc返回成功。窄屏东京按钮传送后显示东京塔卡与城市信息。未测试真实手机GPU。
- 同机位对比与窄屏证据见 `docs/validation/round-2/`，均为实际游戏截图。

## 下一步

先评审这一小块街区的建筑比例与棕榈密度，再决定是否扩展至相邻街块。海水、周围白色高层、地标贴图和角色仍保留既有风格；本轮不宣称全城已达到参考视频的写实程度。
